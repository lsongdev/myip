    About these measurements +

    Speed is measured in megabits per second (Mbps). The test warms up each transfer, then samples the sustained rate until it stabilizes or reaches 12 seconds per direction. Parallel mode uses three concurrent transfers; your browser may share an HTTP connection between them.

    Latency is the median HTTP response time after an initial warm-up request. Jitter is the average change between consecutive measurements. Loaded latency is measured while transferring data. These are browser measurements to the selected server, and can be affected by Wi-Fi, VPNs, proxies, and server capacity.

    IP addresses are checked with ipify, with icanhazip as a fallback. IPv6 is checked independently and may be unavailable on your network. DNS queries go to Google Public DNS. Location queries go to the provider you select. “Hide IP details” masks addresses and locations on this page, including copied speed results. No test history is saved.

    Website connectivity uses small, direct browser HEAD requests to public resources, with 12 attempts per site on each run. Each dot records a response, timeout or failure. A response confirms the probe was reached; it does not verify the full website or its HTTP status, which cross-origin responses may hide. Times include browser and connection setup overhead and are not ICMP ping. Timeouts or unavailable results can also be caused by browser restrictions, extensions or the resource itself. Detection pauses during a speed test and stops when the tab is hidden. The number shows the median of successful responses in the current run; it stays visible while the next request is pending. Dots and the status label show each individual attempt. Starting a new check resets the selected sites' dots. Results stay only in this tab.
